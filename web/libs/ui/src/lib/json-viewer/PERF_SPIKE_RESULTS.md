# FIT-2006 — Virtualized JSON viewer spike results

**Epic:** [FIT-2007](https://humansignal.atlassian.net/browse/FIT-2007)  
**Spec:** [Notion design spec](https://app.notion.com/p/3847094e54c881cb9b32ff31c4b69e7a)  
**Date:** 2026-06-19  
**Branch:** `fb-fit-2006`

## Executive summary

**Chosen library: `react-json-virtualization@0.7.0`**

On Task Source–shaped fixtures at depth-2 expansion, `react-json-virtualization` delivers **4–9× faster initial mount** than `json-edit-react` while rendering **~5 DOM nodes** instead of **1k–85k**. It is compatible with our **React 18.3.1** stack (`peerDependencies.react: ">=18"`).

`react-obj-view` is **rejected** — it declares `peerDependencies: { react: "19" }` and cannot import in our monorepo (fails with `Export named 'use' not found`).

Implementation risk is **low–medium**: most `JsonViewer` toolbar/state logic stays in the existing wrapper; the tree renderer swaps behind the feature flag. Custom filters, search, Reader View, and theme need thin adapter shims (documented below).

## Benchmark methodology

| Parameter | Value |
|---|---|
| Runtime | Bun 1.3.11, jsdom 22 |
| Fixtures | Task Source–shaped nested JSON (~10 KB / ~100 KB / ~1.1 MB on disk) |
| Expansion | `collapse` / `initialExpandDepth = 2` (root + one level) |
| Viewport | 500 px height |
| Runs | 1 warmup + 3 measured per library/fixture |
| Script | `libs/ui/scripts/json-viewer-benchmark.tsx` |
| Config | `BUN_CONFIG=libs/ui/scripts/benchmark.bunfig.toml` (isolates React 18 resolution in monorepo) |
| Raw output | `benchmark-results.json` (same directory) |

**Caveats**

- jsdom mount time approximates initial render cost; it does not measure scroll frame budget.
- Virtualized libraries defer row materialization — DOM node counts understate visible work but correctly show **full-tree vs windowed** difference.
- Scroll smoothness for 1 MB payloads was validated qualitatively against the library’s [live demo](https://mietoprogramming.github.io/react-json-virtualization/) and upstream mode benchmarks (`npm run bench:modes` in the package README).

## Benchmark results

### Initial mount time (median ms)

| Fixture | json-edit-react | react-json-virtualization | Speedup |
|---|---:|---:|---:|
| 10 KB | 25.4 | 2.89 | **8.8×** |
| 100 KB | 120.1 | 27.3 | **4.4×** |
| 1 MB | 1,096.9 | 134.6 | **8.2×** |

### DOM nodes after mount (depth 2)

| Fixture | json-edit-react | react-json-virtualization |
|---|---:|---:|
| 10 KB | 1,112 | 5 |
| 100 KB | 8,548 | 5 |
| 1 MB | 85,416 | 5 |

At 1 MB, `json-edit-react` allocates **~85k DOM nodes** for a partially collapsed tree — this matches production freezes reported when filters expand large annotation arrays. `react-json-virtualization` keeps a constant small DOM footprint via windowing.

## Library evaluation

### Selected: `react-json-virtualization`

| Criterion | Assessment |
|---|---|
| Virtualization | Yes — `VirtualizeJSON.Collapsable` windowed rows |
| React 18 | Yes (`peerDependencies.react: ">=18"`) |
| Bundle | ~MIT, no MUI/Chakra |
| Search | `searchQuery`, `activeMatchIndex`, `onSearchMetadata` — host-owned UI fits our toolbar |
| Filtering | `rowFilter`, `pathFilterQuery` — can mirror `customFilters` |
| Theming | Token-based `theme` prop + CSS overrides for LS variables |
| Collapse depth | `initialExpandDepth`, controlled `expandedPaths` |
| Maintenance | Active (v0.7.0, TypeScript-first, built-in bench suite) |

### Rejected candidates

| Library | Reason |
|---|---|
| **react-obj-view** | Requires React 19; cannot run in LSO/LSE today. Virtualization story unverified in our stack. |
| **@textea/json-viewer** | Hard dependency on **MUI** (`@mui/material`). Conflicts with `@humansignal/ui` / Tailwind design system; would force duplicate component libraries and theme plumbing. |
| **react-json-view-lite** | Lightweight tree viewer but **no virtualization** — still renders full expanded subtrees in DOM. Does not address 1 MB Task Source jank. |
| **json-edit-react** (status quo) | Baseline only. Acceptable at 10 KB; degrades linearly to **~1.1 s mount** and **85k nodes** at 1 MB. |

## Parity matrix (`JsonViewerProps`)

Legend: **Native** = library supports directly · **Shim** = wrapper adapter in `@humansignal/ui` · **N/A** = unchanged wrapper code

| Prop | Current (`json-edit-react`) | `react-json-virtualization` | FIT-2009 approach | Risk |
|---|---|---|---|---|
| `data` | `data` object | `json` string (`JSON.stringify`) | Serialize in wrapper | Low |
| `viewOnly` | `restrictEdit/Delete/Add` | Read-only viewer (no edit APIs) | Omit edit affordances | Low |
| `showSearch` | Toolbar + `searchText` | Host toolbar + `searchQuery` | Keep existing search UI | Low |
| `showFilters` | Toolbar filter buttons | Host toolbar + `rowFilter` / `pathFilterQuery` | Keep existing filter UI | Medium — `nodeData` shape differs |
| `showCopyButton` | Wrapper `Button` | N/A (wrapper) | Unchanged | Low |
| `customFilters` | `searchFilter` + `filterFn(nodeData)` | `rowFilter(context)` | **Shim:** map `nodeData` adapter from row context (`path`, key, value) | Medium |
| `readerViewThreshold` | `customButtons` → `ReaderViewButton` | `rowDecorator` per row | **Shim:** attach Reader View action on long strings | Medium |
| `storageKey` | `localStorage` in wrapper | N/A (wrapper) | Unchanged | Low |
| `toolbarExtra` | Rendered in controls row | N/A (wrapper) | Unchanged | Low |
| `minHeight` / `maxHeight` | Container inline styles | `height` on viewer + container CSS | Map `maxHeight` → `height` | Low |
| `fontSize` | `rootFontSize` | CSS on container / theme tokens | **Shim:** pass via `className` + CSS var | Low |
| `stringTruncate` | `stringTruncate` prop | No direct prop | **Shim:** `rowRenderer` truncate + expand on click | Medium |
| `collapse` | `collapse` depth / `resetKey` | `initialExpandDepth`, controlled expansion | Map filter-reset expand to `expandedPaths` | Medium |
| `className` | Outer wrapper | `className` on viewer + wrapper | Unchanged | Low |
| `inset` | CSS module | CSS module on wrapper | Unchanged | Low |
| `onCopy` | Wrapper clipboard handler | N/A (wrapper) | Unchanged | Low |

### Behaviors not exposed as props (must preserve)

| Behavior | Current | Virtualized path | Risk |
|---|---|---|---|
| Search matches keys, paths, primitives | `matchNode` + `fallbackNodeMatch` | `searchQuery` + custom match if needed | Medium — verify path segment search |
| Filter expand without full deep open | `setCollapseDepth(Infinity)` capped by filter | Expand matching paths only via `expandedPaths` | Medium — avoid 3k+ annotation blowout |
| `showCollectionCount` | `showCollectionCount={true}` | No equivalent | Low — add badge in `rowDecorator` or drop if invisible in QA |
| Label Studio theme / CSS vars | `labelStudioTheme` + SCSS `:global` | `theme` token overrides + SCSS | Low |
| Copy icon in editor chrome | `icons.copy` | N/A — copy stays in wrapper toolbar | Low |

## Recommendation for FIT-2009

1. Add `react-json-virtualization` as a **production** dependency (currently spike-only `devDependency`).
2. Behind `fflag_feat_fit_2007_virtualized_json_editor_short`, render `VirtualizeJSON.Collapsable` inside existing `JsonViewer` chrome.
3. Implement a **`nodeData` adapter** so `customFilters[].filterFn` and search helpers keep the same call signature without call-site changes.
4. Port `ReaderViewButton` to `rowDecorator` actions for long strings.
5. Keep `json-edit-react` path as default until FIT-2011 QA sign-off.
